# FK Pay API v1

API принимает платежи **только с внутреннего USDT-баланса FK Wallet**. Crypto Pay/CryptoBot не подключён. Ключ FK Pay и токен Crypto Pay — разные вещи. Административное начисление не создаёт криптовалютный резерв.

## Быстрое подключение

1. Запустите Node.js FK Wallet, настройте `.env`, включая постоянный `APP_ENCRYPTION_KEY`.
2. Войдите через Telegram → «Для разработчиков» → создайте приложение. Укажите публичный HTTPS webhook URL своего сервера, если нужны уведомления.
3. Сохраните API-ключ и webhook-секрет: они показываются один раз. На сервере FK Wallet API-ключ хранится только в виде SHA-256 хеша, webhook-секрет зашифрован AES-256-GCM.
4. Передавайте API-ключ **только со своего сервера**. В код браузера и Telegram Mini App ключ не вставляйте.
5. Создайте счёт, передайте покупателю `telegramUrl`. После оплаты обработайте webhook и подтвердите статус через API.

Базовый адрес API: ваш `PUBLIC_URL`, например `https://wallet.example.com`. В запросах: `Authorization: Bearer fkw_...`. API не требует Telegram cookie, Origin или CSRF — они предназначены для личного кабинета. Сторонний сайт обращается к API через свой backend; браузерный CORS не включён.

## Node.js SDK

В архиве есть `sdk/fk-pay.mjs`, внешние зависимости не нужны:

```js
import { FKPay } from './sdk/fk-pay.mjs';
const pay = new FKPay({
  baseUrl: process.env.FK_PAY_BASE_URL,
  apiKey: process.env.FK_PAY_API_KEY
});

// Сохраните этот UUID у заказа ДО запроса. При повторах используйте тот же UUID.
const requestKey = FKPay.idempotencyKey();
const invoice = await pay.createInvoice({
  asset: 'USDT',
  amount: '10.123456',
  description: 'Заказ №123',
  payload: 'order-123',
  expiresIn: 3600
}, requestKey);
console.log(invoice.telegramUrl || invoice.paymentUrl);
const status = await pay.getInvoice(invoice.id);
```

Сумма — **строка** с точкой, до 6 десятичных знаков, от `0.000001` до `1000000`. Float-числа, отрицательные суммы и научная запись отвергаются. В ответе сумма имеет 6 десятичных знаков. `expiresIn` — целое от 60 до 86400 секунд, по умолчанию 3600. `description` до 200 символов; `payload` — строка до 2048 UTF-8 байт. В payload передавайте ID заказа, не пароли, токены и персональные данные.

## Методы

| Метод | Назначение |
| --- | --- |
| `POST /v1/invoices` | Создать счёт; обязателен UUID в `Idempotency-Key`. |
| `GET /v1/invoices/:id` | Счёт только текущего приложения. |
| `GET /v1/invoices?status=paid&before=123` | До 50 счетов, `next` — курсор следующей страницы. |
| `POST /v1/invoices/:id/cancel` | Отменить неоплаченный счёт; повторная отмена безопасна. |
| `POST /v1/payouts` | Выплатить пользователю FK Wallet по `@username`; обязателен UUID в `Idempotency-Key`. |
| `GET /v1/payouts/:id` | Получить выплату только текущего приложения. |
| `GET /v1/payouts?before=123` | До 50 выплат, `next` — курсор следующей страницы. |
| `GET /v1/balance` | Доступный внутренний баланс **кошелька владельца**, общий для всех его приложений. `scope: owner_wallet`. |

SDK: `createInvoice`, `getInvoice`, `listInvoices`, `cancelInvoice`, `createPayout`, `getPayout`, `listPayouts`, `getBalance`. При сетевом сбое SDK не создаёт новый ключ автоматически: повторите создание с прежним ключом и прежними параметрами. Повтор возвращает тот же счёт или выплату; изменение параметров с прежним ключом — `409`.

Пример ответа создания:

```json
{
  "id": "UUID-счёта",
  "appId": "UUID-приложения",
  "appName": "Магазин",
  "asset": "USDT",
  "amount": "10.123456",
  "description": "Заказ №123",
  "payload": "order-123",
  "status": "active",
  "expiresAt": "2026-10-27T12:00:00.000Z",
  "createdAt": "2026-10-27T11:00:00.000Z",
  "paidAt": null,
  "payerId": null,
  "operationId": null,
  "paymentUrl": "https://wallet.example.com/#pay=UUID-счёта",
  "telegramUrl": "https://t.me/YourWalletBot?startapp=pay_UUID-счёта"
}
```

Статусы: `active`, `paid`, `expired`, `cancelled`. Оплаченные счета и их условия неизменяемы. Отмена не возвращает деньги; возвраты отдельным API пока не реализованы.

`telegramUrl` возвращается, если заполнен `TELEGRAM_BOT_USERNAME`. В @BotFather настройте **Main Mini App** вашего бота с адресом `PUBLIC_URL`: только кнопки меню недостаточно для `?startapp=`. В чужом боте отправляйте обычную URL-кнопку на `telegramUrl`, чтобы покупатель вошёл через **вашего** бота FK Wallet. Нельзя открыть FK Wallet через web_app-кнопку чужого бота: подпись initData будет выдана другим токеном. `paymentUrl` — прямая ссылка на страницу счёта; вне Telegram она покажет счёт, но для оплаты всё равно потребуется вход в FK Wallet.

При оплате покупатель видит приложение, описание, сумму и срок; подтверждает списание. Сервер проверяет баланс, статус, срок и сумму, атомарно создаёт две записи журнала и зачисляет сумму кошельку владельца приложения. Комиссий пока нет. Оплата собственного приложения запрещена. Повтор запроса оплаты не списывает средства второй раз. Персональные переводы по username — отдельная функция, в этой версии не включены.

## Выплаты пользователям FK Wallet

```js
const payoutKey = FKPay.idempotencyKey(); // сохраните до запроса
const payout = await pay.createPayout({
  recipient: '@username',
  amount: '5.000000',
  description: 'Кэшбэк за заказ №123',
  payload: 'reward-123'
}, payoutKey);
```

Выплата выполняется внутри FK Wallet: сумма атомарно списывается с общего баланса владельца магазина и сразу зачисляется пользователю. CryptoBot не вызывается. Получатель задаётся только Telegram `@username` и должен ранее открыть FK Wallet, чтобы его профиль существовал. Выплата самому владельцу магазина запрещена. `description` — до 200 символов, `payload` — до 2048 байт. Один UUID всегда означает одну выплату: безопасный повтор возвращает прежний результат, а другие параметры с тем же UUID дают `409`.

Ответ содержит `status: "completed"`, `operationId`, сумму, приложение и `recipient.username`. В истории магазина появляется исходящая операция, у пользователя — входящая «Выплата от магазина». Общая сумма внутренних балансов не меняется.

## Webhooks

Уведомление создаётся в той же транзакции SQLite, что и оплата. Доставка как минимум один раз: получатель **обязан** хранить обработанные event ID в постоянной базе. Повторная доставка после сбоя или перезапуска возможна даже после успешного первого приёма.

Заголовки:

```text
FK-Event-Id: UUID-события
FK-Timestamp: UNIX-время отправки в секундах
FK-Signature: sha256=HEX_HMAC
Content-Type: application/json
```

Подпись: `HMAC-SHA256(webhookSecret, timestamp + "." + rawBody)`. Используйте **исходные байты HTTP тела**, не JSON после повторной сериализации. Временное окно проверки — ±300 секунд. При повторной доставке event ID и тело остаются прежними, timestamp и подпись формируются заново.

```js
import { verifyFKWebhook } from './sdk/fk-pay.mjs';
const valid = verifyFKWebhook({
  secret: process.env.FK_WEBHOOK_SECRET,
  timestamp: request.headers['fk-timestamp'],
  signature: request.headers['fk-signature'],
  rawBody: bodyBuffer
});
if (!valid) { /* HTTP 401, не обрабатывать */ }
```

Тело:

```json
{
  "id": "UUID-события",
  "type": "invoice.paid",
  "createdAt": "2026-10-27T11:05:00.000Z",
  "data": { "invoice": { "id": "UUID-счёта", "status": "paid", "amount": "10.123456", "asset": "USDT", "payload": "order-123" } }
}
```

В реальном теле объект invoice содержит все поля из ответа API. Убедитесь, что event ID в теле совпадает с заголовком. Затем запросите счёт через `/v1/invoices/:id` и сопоставьте `appId`, `status`, `asset`, `amount`, `payload` и ожидаемый ID счёта со своим заказом. **Не выдавайте товар по возвращению покупателя на страницу или по одному полю `status` в браузере.**

Подтверждайте доставку кодом `2xx` только после надёжной записи результата. Ответы `3xx` не перенаправляются, `4xx/5xx`, таймаут и сетевые ошибки повторяются: до 8 попыток с задержками 30, 60, 120, 240, 480, 960, 1920 секунд. Полный таймаут отправки 8 секунд; DNS — до 5 секунд. Очередь работает внутри Node.js процесса; он должен постоянно работать. Историю и повтор после исчерпания попыток можно открыть в кабинете.

Webhook URL: только HTTPS на порту 443 без credentials и `#`; адрес должен разрешаться в публичные IP. Локальные сети, loopback, metadata, специальные адреса и переходы по redirect заблокированы. DNS проверяется заново при каждой попытке, соединение привязывается к проверенным адресам. Для локальной разработки используйте публичный HTTPS endpoint или проверку статуса; отключателя этой защиты нет.

При смене URL ожидающие отправки отменяются; уже выполняющийся сетевой запрос может завершиться. Failed/cancelled события можно поставить в очередь на новый URL вручную. Доставленные события повторно отправлять через кабинет нельзя. События не создаются для оплат, прошедших без настроенного webhook URL; эти оплаты проверяйте через API.

## Полный пример магазина

Есть `examples/merchant-server.mjs` и `examples/.env.example`:

```bash
cp examples/.env.example examples/.env
# Заполните параметры приложения из кабинета
node --env-file=examples/.env examples/merchant-server.mjs
```

Сервер по умолчанию слушает `127.0.0.1:4000`. `POST /orders` создаёт заказ с ценой `5.000000 USDT`, выбранной сервером, сохраняет ключ повтора в SQLite и возвращает ссылку оплаты. `POST /orders/:id/invoice` безопасно повторяет запрос того же заказа. `GET /orders/:id` показывает состояние. `POST /fk-webhook` проверяет исходное тело, подпись, срок, сверяет счёт через FK Pay и атомарно сохраняет receipt и оплату заказа. Повторное уведомление не оплачивает заказ второй раз.

Это учебный backend: перед публичным использованием добавьте авторизацию покупателей, ваш каталог и лимиты запросов. Выдача товара здесь не выполняется. Для внешних действий (письмо, лицензия, доставка) используйте свою очередь с надёжным повтором и защитой от дубликатов; не полагайтесь на одноразовый console.log после обновления заказа.

## Ключи, доступ и лимиты

Ключ даёт доступ к счетам и выплатам одного приложения, чтению общего внутреннего баланса владельца и списанию этого баланса для выплат зарегистрированным пользователям FK Wallet. Он не позволяет списывать баланс покупателя, менять административный баланс или отправлять криптовалюту. Храните ключ только на backend и защищайте свой endpoint запуска выплат. Покупатель сам авторизуется и подтверждает оплату. Перевыпуск немедленно отключает прежний ключ. Отзыв не отменяет уже выполненные операции. До 10 приложений на пользователя, страницы по 50 записей, сумма одной операции до 1 000 000 USDT, баланс пользователя до 100 000 000 USDT.

Все действия кабинета проверяют владельца по серверной Telegram-сессии. Для API клиентов нет общего доступа по Telegram ID. Коды ошибок: `400` неверные параметры, `401` ключ/сессия, `403` права/Origin/CSRF, `404` отсутствующий или чужой объект, `409` конфликт/нехватка средств/истечение, `429` лимит, `503` не настроен ключ шифрования или недоступна служба. Тело ошибки: `{ "error": "описание" }`.

Резервируйте SQLite вместе с постоянным `APP_ENCRYPTION_KEY`. Не меняйте ключ при перезапуске и не коммитьте `.env`. Приложение с существующими webhook-секретами не запустится с чужим ключом. Сервер рассчитан на один процесс/постоянный диск; миграция старой базы выполняется при старте без потери записей журнала.
