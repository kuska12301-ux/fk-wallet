# FK Wallet / FK Pay — Node.js + Telegram Mini App

Готовый исходный проект: кошелёк, вход через Telegram, админка, SQLite, корректировки баланса, кабинет разработчика, приложения и API-ключи, счета и оплата с внутреннего баланса, подписанные webhooks с очередью, SDK Node.js и пример магазина. Стартовый баланс каждого пользователя — 0 USDT. Тестовых начислений и обхода входа нет.

**Crypto Pay ещё не подключён.** Пополнение и вывод в CryptoBot, пользовательские переводы, возвраты и merchant payouts пока не реализованы. Администратор изменяет внутренние обязательства сервиса перед пользователем; эти изменения не создают USDT, не пополняют резерв и не отправляют криптовалюту. Журнал содержит административные корректировки и оплаты счетов. У оплаты две записи — списание покупателя и зачисление владельцу приложения — с одним номером операции.

## Что вводить в окружении

Скопируйте `.env.example` в `.env` в корне проекта либо задайте переменные в панели хостинга. Команда `npm start` читает `.env`, если он есть; без файла использует окружение хостинга. Настоящие токены вводятся только на вашем сервере или в секретах хостинга; файл `.env` не публикуйте.

| Переменная | Что указать |
| --- | --- |
| `BOT_TOKEN` | Токен **вашего Telegram-бота** из @BotFather. Не токен Crypto Pay. |
| `ADMIN_TELEGRAM_IDS` | Ваш **числовой Telegram ID**, например `123456789`. Несколько администраторов: `123456789,987654321`. Не @username и не ID бота. |
| `APP_ENCRYPTION_KEY` | Постоянный ключ шифрования webhook-секретов: 64 hex-символа. Генерация: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Без ключа FK Pay отключён. Не менять при перезапусках. |
| `TELEGRAM_BOT_USERNAME` | Username вашего бота без @. Для t.me ссылок оплаты также настройте Main Mini App в @BotFather с адресом PUBLIC_URL. |
| `PUBLIC_URL` | HTTPS адрес Node.js приложения, например `https://wallet.example.com`, без пути и параметров. Должен совпадать с адресом, открываемым в Telegram. |
| `HOST` | `127.0.0.1` при nginx на том же VPS. Для Docker обычно `0.0.0.0`. |
| `PORT` | Внутренний порт сервера, по умолчанию `3000`. |
| `NODE_ENV` | `production` на сервере. |
| `DB_PATH` | `./data/fk-wallet.sqlite` или путь на постоянном диске. При перезапусках и обновлениях файл не удалять. |
| `AUTH_MAX_AGE_SECONDS` | `300`: возраст подписанных данных Telegram при входе. |
| `SESSION_TTL_SECONDS` | `43200`: срок сессии, 12 часов. |

Если Telegram ID неизвестен: отправьте сообщение своему боту, проверьте `message.from.id` в Telegram Bot API `getUpdates` в своём окружении. После первого входа ID также виден в профиле, если у аккаунта нет username. Не используйте чужой ID. Права задаются только в `.env`; для изменения перезапустите сервер.

## Запуск

Требуется Node.js 24 LTS или новее. Внешних npm-зависимостей нет. Используется встроенный `node:sqlite` (в Node 24 может выводиться ExperimentalWarning).

PowerShell:

```powershell
Copy-Item .env.example .env
# Заполните .env в редакторе
npm test
npm start
```

Linux:

```bash
cp .env.example .env
# Заполните .env в редакторе
npm test
npm start
```

Разместите Node.js за HTTPS reverse proxy, направляющим **и страницы, и `/api/*`, `/v1/*`** на `127.0.0.1:3000`. Передавайте заголовок `Origin` без изменения. Нужен постоянный диск для SQLite; этот вариант рассчитан на один экземпляр Node.js, не на несколько реплик. Лимитер запросов работает на IP соединения, поэтому при nginx он общий для запросов через прокси: для большого трафика перенесите лимитирование на доверенный прокси с отдельными лимитами по пользователям.

Минимальный фрагмент nginx внутри уже настроенного HTTPS `server` с сертификатом:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_http_version 1.1;
}
```

Для локальной проверки запуска можно указать `NODE_ENV=development` и `PUBLIC_URL=http://127.0.0.1:3000`. Настоящий вход в Mini App требует HTTPS URL, доступного Telegram. Веб-страница вне Telegram не даёт права администратора.

## Подключение к боту

1. Создайте бота в @BotFather, заполните `BOT_TOKEN` и `ADMIN_TELEGRAM_IDS`.
2. Запустите Node.js на своём HTTPS домене, заполните `PUBLIC_URL`.
3. Выполните `npm run bot:setup`: команда настроит кнопку меню «FK Wallet» у вашего бота. Можно настроить её вручную в @BotFather через Bot Settings → Menu Button.
4. Откройте личный чат с ботом и нажмите кнопку «FK Wallet». Вход проверяется на сервере по HMAC подписи `Telegram.WebApp.initData` и времени выдачи.
5. Для ID из `ADMIN_TELEGRAM_IDS` появится вкладка «Админка», адрес `/#admin`.

Ссылка `chatgpt.site` — статическое превью. Она **не запускает Node.js, не хранит баланс и не открывает админские права**. Для рабочего кошелька используйте собственный домен, на котором работает этот сервер. Токен бота и ваш ID для запуска в текущей сессии не предоставлены, поэтому настоящий вход ещё не проверен с вашим ботом.

## Работа администратора

- Пользователь должен сначала открыть Mini App через Telegram, чтобы зарегистрироваться с нулевым балансом.
- Найдите его по ID или username. Нажмите строку пользователя, чтобы подставить ID.
- Выберите начисление или снятие, сумму USDT (до 6 знаков после точки), обязательную причину.
- Проверьте отдельное окно подтверждения. Снятие ниже нуля запрещено.
- Для каждого изменения журнал сохраняет операцию, пользователя, ID администратора, сумму, причину, время UTC и баланс после изменения.
- История не редактируется и не удаляется через API; отмена оформляется новой противоположной корректировкой с объяснением.
- Повтор запроса с тем же ключом не выполняет изменение второй раз. Если сеть оборвалась, повторите через кнопку в окне подтверждения. После перезагрузки страницы перед новой операцией сначала проверьте журнал.

Сессия использует HttpOnly cookie и bearer-токен только в памяти страницы для Telegram Web, где сторонние cookies могут блокироваться. Токен не сохраняется в localStorage. Есть проверка Origin и CSRF, срок годности входа, запрет доступа обычным пользователям, атомарная запись баланса и журнала. Очередь webhooks работает в этом же постоянно запущенном процессе. Суммы хранятся целыми микродолями USDT, без арифметики с дробными float. Лимит одной корректировки — 1 000 000 USDT; баланс пользователя — до 100 000 000 USDT. Сам администратор и владелец сервера имеют привилегированный доступ; SQL-триггеры защищают журнал от обычного изменения приложением, но не от владельца файла базы.

## Серверные методы

Все методы ниже предназначены для интерфейса FK Wallet, не являются открытым merchant API.

| Метод | Назначение |
| --- | --- |
| `POST /api/auth/telegram` | Вход: `{ "initData": "подписанные данные Telegram" }`. |
| `GET /api/me` | Профиль, баланс, признак администратора, CSRF-токен. |
| `GET /api/transactions?before=...` | Только собственная история, по 50 записей. |
| `POST /api/logout` | Завершение сессии. |
| `GET /api/admin/summary` | Число пользователей, общий внутренний баланс и число операций. |
| `GET /api/admin/users?search=...&before=...` | Поиск и список пользователей, по 50 записей. |
| `GET /api/admin/operations?userId=...&kind=...&before=...` | Журнал всех пользователей; `kind`: `admin_credit` / `admin_debit` / `invoice_credit` / `invoice_debit`. |
| `POST /api/admin/adjustments` | Корректировка: `{ "userId":"123456789", "direction":"credit", "amount":"10.000001", "reason":"Основание" }`. `direction`: `credit` / `debit`. |

Запросы требуют cookie сессии или заголовок `Authorization: Bearer <sessionToken>` из ответа входа. Запросы изменения дополнительно требуют совпадающий `Origin` и `X-CSRF-Token` из `/api/me`. Корректировки также требуют UUID в `Idempotency-Key`. Сервер никогда не доверяет Telegram ID, переданному браузером для определения прав: права вычисляются по проверенной сессии.

Если npm недоступен, команды можно выполнить напрямую: `node --test server/*.test.mjs`, `node --env-file=.env server/index.mjs`, `node --env-file=.env server/setup-bot.mjs`.

## Данные и резервные копии

Сохраняйте APP_ENCRYPTION_KEY вместе с резервной копией. Старая база автоматически обновляется при старте с сохранением журнала; перед обновлением сделайте копию. Каталог `data/` содержит SQLite и файлы WAL. Для простой согласованной резервной копии остановите Node.js, скопируйте весь каталог `data/`, затем запустите снова. Нельзя копировать только основной `.sqlite` файл при активной записи без SQLite backup API. Храните резервные копии отдельно с ограниченным доступом. Обновление исходников не должно удалять `data/` и `.env`.

Документация: [проверка Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [SQLite в Node.js 24](https://nodejs.org/docs/latest-v24.x/api/sqlite.html).


## FK Pay для внешних проектов

Полная спецификация: [API.md](API.md). SDK: `sdk/fk-pay.mjs`. Учебный backend магазина: `examples/merchant-server.mjs` и `examples/.env.example`.

Заполните постоянный `APP_ENCRYPTION_KEY`, откройте Telegram → «Для разработчиков», создайте приложение и сохраните одноразово показанные API-ключ и webhook-секрет. Приложения создаются в базе сервера, а не в localStorage. Ключи перевыпускаются и отзываются в кабинете. Потерянный webhook-секрет не восстанавливается: создайте новое приложение.

Внешний проект создаёт счёт через `POST /v1/invoices` (с UUID Idempotency-Key), отправляет покупателю `telegramUrl`, принимает подписанный webhook `invoice.paid` и сверяет оплату через `GET /v1/invoices/:id`. Ключ хранится только на backend. До 10 приложений на пользователя. Ключ изолирует счета приложения; `/v1/balance` возвращает общий внутренний кошелёк владельца. Комиссии и возвраты пока не реализованы.

Для `telegramUrl` заполните `TELEGRAM_BOT_USERNAME` и настройте Main Mini App в @BotFather. Кнопка меню от `bot:setup` сама по себе этого не заменяет. В чужом боте отправляйте URL-кнопку на `telegramUrl`, чтобы покупатель вошёл через вашего бота FK Wallet.

Методы кабинета: `GET/POST /api/developer/apps`, `PATCH /api/developer/apps/:id`, `POST .../rotate-key`, `POST .../revoke-key`, `GET/POST .../invoices`, `POST .../invoices/:invoiceId/cancel`, `GET .../events`, `POST .../events/:eventId/retry`. Публичный просмотр: `GET /api/invoices/:id`; подтверждение покупателем: `POST /api/invoices/:id/pay` с `{amount}` и UUID Idempotency-Key. Секреты API внешних проектов не заменяют Telegram-сессию для оплаты.

Webhook URL: публичный HTTPS на порту 443. Внутренние IP, metadata, loopback и redirects запрещены; DNS перепроверяется и закрепляется при каждой попытке. Доставка до 8 раз с сохранением event ID; получатель должен хранить обработанные события в своей базе. История доставки доступна в кабинете. После смены URL недоставленные события отменяются; failed/cancelled можно повторить вручную.

При значительном трафике настройте лимиты на доверенном reverse proxy: текущие лимиты (20 входов / 300 API-запросов в минуту на IP соединения) при nginx могут быть общими для всех его пользователей. Один процесс Node.js с постоянным SQLite-диском; не несколько реплик.

С вашим реальным ботом, доменом и внешним webhook-сервером проверка пока не выполнена. Автотесты проверяют полный платёжный путь и пример магазина в изолированных базах; эти данные не поставляются в проекте.
